`RunAgent` never fails a bundle for an element-level problem. It routes the
failure to `.errors` and moves on. A record there means the activation
committed nothing at all — so consuming this stream is not optional
housekeeping, it is how you find out that a key was touched and produced
nothing.

{/*
  Two lanes of the same bundle, because the whole point of this page is a
  contrast: one key's activation fails and commits nothing, and the bundle it
  was in commits anyway. A single-lane drawing can show the dead letter but
  cannot show what did *not* happen around it, which is the part readers get
  wrong.

  Geometry note for anyone editing this: the coordinate space is 620 units
  wide on purpose. The prose column on this site is ~630px, so a 620-wide
  viewBox renders at roughly 1:1 and the 11px labels stay 11px. Authoring
  against a 1000-wide box (as the landing-page diagram does, in a much wider
  container) scales the type down to seven-ish pixels and forces a sideways
  scroll on a desktop, which is exactly the failure this component exists to
  avoid.
*/}

{/*
  The record diagram. `docs/errors.md` draws this same structure as an ASCII
  tree in a bare code fence — unreadable on a phone, invisible to a screen
  reader, and unable to carry the stream colour. The fence stays where it is
  (this site renders the repository file verbatim, byte for byte, and that
  contract is worth more than the fence costs), but the reader meets the real
  drawing first, so the fence below reads as a detail rather than as the
  explanation.

  The nesting is the interesting part: the value on the topic is an
  AgentEnvelope, and the record itself is bytes inside `external_event`. That
  wrapping is what makes the errors topic replayable as a RunAgent *input*.
*/}
