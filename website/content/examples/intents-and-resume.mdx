Two activations, one logical unit of work. `ctx.act` stages the intent and returns its
deterministic id; `Suspend` persists the continuation and arms the fail-closed timeout.

The example can name the intent id *before* the pipeline runs, because the id is
`uuid5(namespace, key|seq|step_index)` — a pure function of the activation's position.
That is what makes deduplication a lookup rather than a guess.

<HitlReinjection />

Follow the three faint lines out of the middle box. The same value is what
`ctx.act` stamps on the intent, what the outbox deduplicates on, and what the
resume is matched against — and because nothing in that derivation reads a clock
or a counter, the `intent_id_for(b"acct-1", 0, 0)` call in `main` below arrives
at it with no pipeline built and no element in flight. A replayed bundle that
walks the same path mints the byte-identical id, which is the whole
effectively-once argument.

Run it:

```sh
uv run python website/examples/intents_and_resume.py
```
