## 8. Revisions

Recorded during implementation, per the "update the spec first, then the test,
then the code" rule.

1. **The facade tests live in `tests/model/test_facade_budget.py`, not `tests/model/test_facade.py`.** No `test_facade.py` exists: the model-facade suite is split one file per concern (`test_facade_cache.py`, `test_facade_retry.py`, `test_facade_traces.py`, …). The budget's enforcement is one more concern, so it follows the established naming instead of creating the monolith the proposal's snapshot assumed.

2. **The `runtime-metrics` delta was rewritten against the current surface.** The proposal's snapshot predated three merged changes that each widened the closed contract, so the delta as written would have *narrowed* it. Reconciled as follows:
   - The surface is **eleven counters and nine distributions**, not seven and eight: `add-longterm-memory-stores` added `longterm_upserts`, `add-adaptive-batching` added `events_buffered`/`batch_flushes_size`/`batch_flushes_timer` and the `batch_size` distribution. The two new cost distributions are inserted immediately after `tokens`, and `batch_size` stays last.
   - The `agent_errors` reason list carries the reasons that actually exist today — `activation_timeout`, `activation_error`, `budget_exceeded`, `hitl_timeout`, `ttl_wiped_suspension`, `ttl_wiped_batch`, `batch_buffer_overflow` — rather than the four the snapshot listed.
   - The batch-recording paragraph, the batch counter identities, and the "A batch flush is one activation" scenario are carried forward from `add-adaptive-batching`'s delta verbatim, since a MODIFIED requirement replaces the whole requirement body.
   - The "no `AgentConfig` knob controls metrics" parenthetical now names `tool_registry`, the batch knobs, and `max_tokens_per_activation` together.
   - The pipeline-queryable scenario is driven by a `usage_reporting_agent` that reports decoded usage through `ctx.accumulate_usage` — the same call the pydantic-ai adapter makes. The runtime's own `ctx.call_model` never decodes the opaque response bytes, so no plain-runtime pipeline can reach the three usage distributions; standing in for an adapter is what makes the DirectRunner query honest rather than vacuous.

3. **Two pre-existing `mypy --strict` errors are out of scope.** `src/beam_agents/effector/sources.py:212` and `src/beam_agents/effector/sinks.py:154` report `Unused "type: ignore"` on their `from google.cloud import pubsub_v1` guards. Both reproduce on a pristine export of the pre-change tree with a cold cache, neither file is in this change's Impact section, and nothing this change touches is imported by them — they are a `google.cloud` namespace-package resolution artifact of the synced environment, not a regression here.
