## Why

Nothing bounds what one activation may spend. `activation_timeout_s` caps wall time, but a handful of large-context model calls burns real money in well under 30 seconds, and an agent bug that loops on the model runs the meter until the clock — not the budget — kills it. The runtime already has complete usage *plumbing*: providers decode `TokenUsage` per call ([facade.py:53](../../../src/beam_agents/model/facade.py:53)), the facade reports it through the `StagingSink` seam ([facade.py:365](../../../src/beam_agents/model/facade.py:365)), both context surfaces accumulate it (`accumulate_usage`, [context.py:326](../../../src/beam_agents/core/context.py:326) and [context.py:631](../../../src/beam_agents/core/context.py:631)), and `add-runtime-metrics` publishes a per-activation `tokens` distribution from the `ActivationTally` ([metrics.py:111](../../../src/beam_agents/observability/metrics.py:111)). All of it is measurement. Nothing decides.

A budget is a decision, and that makes it a different kind of feature from the metrics that came before it. `add-runtime-metrics` was allowed to read monotonic clocks precisely because "measurement is not decision" — no branch depends on a reading. A `max_tokens_per_activation` check *is* a branch, taken mid-activation, upstream of every intent the activation goes on to mint. Its input must therefore be a pure function of the deterministic activation walk, or a chaos-forced bundle retry (whose calls come back as replay-cache hits) would take a different branch than the original walk and break the byte-identical-intents gate. That constraint — not the counting — is the design problem this change exists to solve.

The same activation-level view is also missing a cost instrument: the `tokens` distribution samples totals only, but input and output tokens are priced differently by every provider, and the split is already decoded into `TokenUsage.prompt_tokens`/`completion_tokens` and then thrown away by the tally.

## What Changes

- **`AgentConfig.max_tokens_per_activation`** ([transform.py:395](../../../src/beam_agents/core/transform.py:395)): a new kw-only field, `int | None = None` (None = unlimited, today's behavior), validated in `__post_init__` following the existing pattern — non-positive values raise `ValueError` at the construction site, and setting it without `decode` also raises, because a budget that cannot read token counts is unenforceable ([context.py:731](../../../src/beam_agents/core/context.py:731) returns "unknown" without a decoder, and unknown must not silently mean free). Threaded `RunAgent → _AgentDoFn → run_activation → ActivationContext`, the same path `tool_registry` and `decode` already ride.

- **`TokenBudget` and `BudgetExceeded` in `model/facade.py`**, beside `TokenUsage` and the existing non-`ProviderError` exceptions (`CircuitOpenError`, `OutputSchemaError` — [facade.py:88](../../../src/beam_agents/model/facade.py:88)). `BudgetExceeded` is deliberately **not** a `ProviderError`: `_call_with_retry` retries on `except ProviderError` ([facade.py:333](../../../src/beam_agents/model/facade.py:333)), and a tripped budget must never be retried against the provider. `TokenBudget.charge(total_tokens)` accumulates and raises once the running total *exceeds* the limit, latching an `exhausted` flag that every later call checks at entry.

- **The budget charges what the agent consumed, not what was billed.** Every model-call response the agent receives is charged its decoded `total_tokens` — **replay-cache hits included**. A hit's bytes are replay-stable and its decoded counts are a pure function of them; provider-reached-ness is not replay-stable (a bundle retry converts misses to hits), so billed-only charging would feed a branch from a value the retry-determinism gate does not hold fixed. The billed/unbilled distinction stays where it belongs — in cost accounting: `accumulate_usage` remains provider-reached-only and `usage_attributes(usage, billed=...)` ([traces.py:110](../../../src/beam_agents/observability/traces.py:110)) is untouched. Two meters, deliberately different, because one is measurement and the other is decision.

- **Enforcement at both model-call surfaces.** `LlmFacade.complete` ([facade.py:242](../../../src/beam_agents/model/facade.py:242)) gains an optional injected `TokenBudget`: an entry check fails fast when the budget is already exhausted (before the cache lookup, so a spent budget serves nothing), and the charge lands in `_finish` right after decode — both the cache-hit and provider paths converge there. `ActivationContext.call_model` ([context.py:469](../../../src/beam_agents/core/context.py:469)), which bypasses the facade and awaits the provider directly, enforces the same two checks itself, decoding once and reusing the result for the trace it already stages. `AgentContext` gains the same optional knob and hands the budget to the facade it builds, so adapters get enforcement for free.

- **Fail-fast through the existing failure path, with a new reason.** `BudgetExceeded` propagates out of the agent like any raise: `run_activation`'s wrap ([loop.py:278](../../../src/beam_agents/core/loop.py:278)) turns it into `ActivationFailed` with a `FailureContext`, and the DoFn's `_failed_activation` ([dofn.py:815](../../../src/beam_agents/core/dofn.py:815)) inspects the cause and routes it as a new `REASON_BUDGET_EXCEEDED = "budget_exceeded"` beside `REASON_TIMEOUT`/`REASON_ERROR` ([dofn.py:115](../../../src/beam_agents/core/dofn.py:115)). The dead letter's detail keeps the `repr(cause)` + `failed_at_step=` shape; the synthesized `ERROR` trace carries the reason, `error.type=BudgetExceeded`, and the `beam_agents.failure.*` position attributes. Everything the activation staged — intents, memory writes, cache inserts, traces, outputs — is discarded whole, exactly as invariant 1 demands: the crossing call is paid for (it happened), but not one downstream effect of it commits.

- **The budget bounds one activation attempt; a resume starts fresh.** The glossary defines an activation as one execution inside `process()`, `activation_timeout_s` and the `iterations` metric are already per-attempt, and spanning resumes would require persisting consumed tokens in the `Continuation` (a proto change) plus untangling double-charging when a resume replays the suspended attempt's calls out of the cache. Per-attempt needs none of that and matches the field's name.

- **Cost metrics: two new billed distributions.** `prompt_tokens` and `completion_tokens` join the `beam_agents.runtime` surface, sampled once per committed activation under the same decoded-usage-only rule as `tokens` ([dofn.py:606](../../../src/beam_agents/core/dofn.py:606)) — the input/output split is what a price sheet multiplies. `ActivationTally` gains the two sums, fed by both surfaces' `accumulate_usage`. The metric surface is a closed contract, so this is a MODIFIED delta on `runtime-metrics`, which also adds `budget_exceeded` to the reasons `agent_errors` counts (the counter partition over `.errors` must stay exact).

## Capabilities

### New Capabilities
- `token-budgets`: the `max_tokens_per_activation` bound — where it is configured, the deterministic charging rule (consumed responses, cache hits included), the fail-fast trip and its sticky latch, the `budget_exceeded` routing to `.errors` with position metadata, and the per-attempt scope.

### Modified Capabilities
- `runtime-metrics`: the fixed metric surface widens from six to eight distributions (`prompt_tokens`, `completion_tokens`), the `agent_errors` reason list gains `budget_exceeded` so the counters still close over `.errors` exactly, the commit-path recording enumeration includes the new pair, and the decoded-usage sampling rule extends to it. **Sequencing:** `runtime-metrics` is introduced by the unarchived `add-runtime-metrics`; this delta applies on top of it and archives after it.
