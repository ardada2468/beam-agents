## 7. Revisions

### Revision 1 — the move/stay record dispositions 13 modules, not design D2's 7 rows

Design D2's table and the spec's parenthetical module list (`core, protos, model, tools, actions, memory, hitl, observability, adapters, effector`) were written before the M2 batch landed. The actual top-level inventory of `src/beam_agents/` is thirteen: the ten listed plus `keys.py` (C34 hot-key sharding), `yaml/` (C36 Beam YAML provider) and `testing/` (the bundle-retry chaos harness). The spec's binding text is "every top-level runtime module", with the list as an illustrative minimum, so no spec edit is required — but the doc must disposition all thirteen or it violates the *Every module has an explicit disposition* scenario. §11 therefore carries thirteen rows, and `test_decision_record_dispositions_every_top_level_module` discovers the list from the filesystem so this cannot drift again.

Two of D2's rationales were also stale and are corrected in the doc rather than reproduced:

- **`model/`** — D2 says "anthropic/openai_compat clients"; `openspec/project.md`'s module map still names a `vertex` provider. Neither is current: the shipped providers are Anthropic, OpenAI-compatible and vLLM (`model/vllm.py`, C26); there is no `vertex.py`. The doc names the three that exist.
- **`adapters/`** — D2 says "protocol + LangGraph". The shipped set is the reference protocol plus LangGraph, Google ADK (C31) and Pydantic AI (C39), over a shared `_transport.py` seam. §9 and §11 state four registered adapters, matching `tests/conformance/_registry.py`.

`memory/` likewise now covers four long-term store backends (C29) and a compaction module (C30); its row says so.

### Revision 2 — the thread-ready checklist gains a fifth box: seed the benchmark baseline

Design D5 enumerates three evidence items (benchmark report, conformance matrix, design partners) plus the final consistency pass. Drafting §12 surfaced a fourth precondition that D5 does not name and that would otherwise be discovered too late: `benchmark-baseline.toml`'s `[medians_ms]` table is **deliberately unseeded**, and `docs/benchmarks.md` forbids seeding it from developer hardware ("the gate runs on CI hardware; a laptop-derived number either blocks every nightly or is so loose it catches nothing"). So there is at present no CI-measured figure of any kind for this runtime, and the benchmark report of D5's first box cannot be produced before the baseline exists.

Adding it as its own checklist box makes the ordering explicit — seed the baseline on CI hardware, *then* produce the comparison report, *then* quote figures — instead of leaving a reader of the checklist to assume a green benchmark run implies quotable numbers. This strengthens D5's consistency guard rather than relaxing it, so no design edit is required; recorded here so the extra box is not mistaken for scope creep.
