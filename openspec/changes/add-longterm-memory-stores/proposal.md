## Why

The only memory an agent has today is the working tier: the per-key `MemoryBlob` behind the [`Memory` facade](../../../src/beam_agents/memory/facade.py:105), hard-capped at 1 MiB, LRU-evicted, and garbage-collected by the `TTL_TIMER`. Anything an agent learns that must outlive that cap — entity profiles, case history, accumulated observations — currently has nowhere durable to go: the working tier evicts it, and writing it anywhere else from inside an activation would violate correctness invariant 5 ("side effects only via intents"). The project constitution already reserves the one sanctioned exception for exactly this tier — "documented idempotent upserts to the long-term MemoryStore keyed by `(key, seq)`" ([project.md:46](../../project.md:46)) — and the module map promises `memory/` "stores (Bigtable/Redis/Firestore/SQL)" ([project.md:60](../../project.md:60)). Neither exists. This change ships the long-term tier: a `MemoryStore` ABC with async `load`/`save`/`search`, four backends behind an optional extra, and an explicit `ctx.memory.longterm` surface whose write path is designed so bundle retries converge instead of duplicating.

## What Changes

- **New `beam_agents.memory.stores` subpackage** with an abstract `MemoryStore` base class exposing `load(entity_key, key)`, `save(record)`, and `search(entity_key, prefix, limit)` as async methods, plus an in-memory implementation for offline tests.
- **A versioned record envelope.** A new additive `LongTermRecord` message in `protos/beam_agents.proto` (with `state_schema_version`, like every message there — [beam_agents.proto:21](../../../protos/beam_agents.proto:21)) is the value all four backends store byte-identically via deterministic serialization; `seq` is additionally stored backend-natively (big-endian, the comparable-bytes trick from [`encode_lease_expiry`](../../../src/beam_agents/effector/dedup.py:264)) so each backend can enforce the upsert guard with its own atomic primitive.
- **Idempotent, seq-guarded upsert.** `save` applies only when the incoming record's `seq` is ≥ the stored one for `(entity_key, key)`; older writes are no-ops. A replayed bundle re-stages byte-identical upserts (the same determinism argument as [`intent_id_for`](../../../src/beam_agents/core/agent.py:43)), so duplicate flushes converge on identical rows — this is what makes the invariant-5 exception safe.
- **Four backends behind one optional extra**, following the `effector` extra pattern ([pyproject.toml:21](../../../pyproject.toml:21)): Bigtable (`CheckAndMutateRow` guard, prefix row scan), Redis (per-entity hash, Lua compare-seq-and-set), Firestore (transactional guard, range query), and SQLAlchemy (async engine, transactional compare-and-upsert, portable across dialects). Client libraries import lazily inside constructors, mirroring [`RedisDedupStore`/`BigtableDedupStore`](../../../src/beam_agents/effector/dedup.py:205).
- **URI-scheme factory** `build_memory_store(scheme, parts)` mirroring [`build_dedup_store`](../../../src/beam_agents/effector/dedup.py:496); [`AgentConfig`](../../../src/beam_agents/core/transform.py:395) gains an optional `longterm_memory` URI validated import-free in `__post_init__`, and the DoFn constructs one store per instance in `setup()` on the bridge loop (a shared client pool, like the httpx pools — not cross-key mutable state).
- **Explicit access via `ctx.memory.longterm` — never automatic.** The [`Memory` facade](../../../src/beam_agents/memory/facade.py:105) gains a `longterm` property returning an activation-scoped handle (raising an actionable error when unconfigured). Working-tier operations never consult the store; nothing is hydrated implicitly.
- **Replay-safe activation semantics.** `longterm.save(...)` stages the upsert in the activation (stamped with the activation's `seq` and `now_ms`); the loop driver flushes staged upserts in the commit tail, after the agent returns and before the DoFn commits, so a failed activation flushes nothing. `load`/`search` run inline, see the activation's own staged saves first (read-your-writes overlay), and the spec states the discipline that keeps replay path-stable: long-term writes are computed from replay-stable inputs and never conditioned on a same-activation long-term read of the same key.
- **Search is a bounded per-entity key-prefix scan**, ordered by key — deliberately not vector/semantic search, which belongs to agent frameworks and has no determinism story.

## Capabilities

### New Capabilities

- `memory-stores`: the `MemoryStore` ABC and its `load`/`save`/`search` contract, the `LongTermRecord` envelope, seq-guarded idempotent upsert semantics, bounded prefix search, the URI factory and optional-extra import boundary, and the Bigtable/Redis/Firestore/SQLAlchemy implementations.

### Modified Capabilities

- `memory-facade`: gains the explicit `longterm` accessor and the activation-side contract around it — staged saves flushed only on activation success, point-in-time reads with a read-your-writes overlay, and the replay discipline for long-term I/O. The existing working-tier requirements (staging, ring semantics, caps, compaction) are unchanged; the facade's own methods remain I/O-free.

- **Depends on** C02 (`add-wire-schemas-and-coders`): the `LongTermRecord` envelope follows the wire-schemas conventions that change established — protobuf for every wire/state schema, deterministic serialization, per-message `state_schema_version`, additive-only evolution — and the working-tier `MemoryBlob` it extends into a second tier comes from the same proto file. Also consumes the archived `memory-facade` capability (the accessor's host, [spec](../../specs/memory-facade/spec.md)) and the stateful-DoFn runtime seams ([`run_activation`](../../../src/beam_agents/core/loop.py:149), [`_commit`](../../../src/beam_agents/core/dofn.py:514)) for staging and flush wiring.
- **New code:** `src/beam_agents/memory/stores/` (`base.py` — ABC, record type, seq encoding, factory, in-memory store; `bigtable.py`, `redis.py`, `firestore.py`, `sql.py`); `LongTermRecord` in `protos/beam_agents.proto` plus regenerated `_pb2` files (regen must stay diff-clean in CI); tests under `tests/memory/stores/`.
- **Modified code:** `src/beam_agents/memory/facade.py` (the `longterm` property and handle), `src/beam_agents/core/context.py` (construct `Memory` with the handle; expose staged upserts to the driver, from both `ActivationContext` and `AgentContext`), `src/beam_agents/core/loop.py` (`ActivationResult` carries staged upserts; flush in the commit tail), `src/beam_agents/core/dofn.py` (store lifecycle in `setup()`/`teardown()`), `src/beam_agents/core/transform.py` (`AgentConfig.longterm_memory` + import-free URI validation), `pyproject.toml` (new `memory-stores` extra: `google-cloud-bigtable`, `redis`, `google-cloud-firestore`, `sqlalchemy[asyncio]`; mirrored into the `integration` dependency group; `PLC0415` per-file ignores for the lazy-import store modules).
