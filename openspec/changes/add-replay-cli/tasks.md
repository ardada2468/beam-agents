## Revisions

### Revision 1 — a failed attempt's clock comes from its `ERROR` event, not an `ACTIVATION_START`

The `replay-cli` requirement said `now_ms` is recovered from "the target activation's traced `ACTIVATION_START.start_ms`", but its own scenario "A failed activation replays to its traced failure position" cannot satisfy that: a failed activation commits nothing (correctness invariant 1), so its *staged* trace events — `ACTIVATION_START` among them — are discarded, and `.traces` carries only the `ERROR` event `_error_trace` synthesizes on the dead-letter route. That event's `start_ms` is the same injected activation clock (every trace timestamp is `now_ms`), so nothing about the mechanism changes; only the sentence describing where to read it was too narrow.

The requirement text now names the fallback explicitly, and `bundle._recover_now_ms` implements it: prefer the attempt's `ACTIVATION_START`, else its first event. `tests/replay/test_bundle.py::test_now_ms_falls_back_to_the_attempts_first_event_when_it_only_errored` pins it, and the semantics gate exercises it end to end against a pipeline-produced trace.

### Revision 2 — a version refusal exits 2; only a migration *gap* is irreproducible

Design D7 listed "migration refusal" among the exit-`3` (irreproducible) causes, while the same document's and the spec's normative text — and tasks 5.2 — put a version refusal at exit `2`. Both readings cannot hold. The resolution kept is the one the spec states normatively and the one that carries information for an operator: a snapshot (or embedded blob) stamped *newer* than the installed package exits `2`, because the remedy is "upgrade beam-agents and retry", not "this activation cannot be reproduced". Exit `3` keeps the cases where the binary is right but the bundle lacks an input: a cache miss, a digest-only entry, a missing event payload, and a migration *chain with a gap* (`MissingMigrationError`/`MigrationStepError`), which is what D7's parenthetical is now worded as.

`bundle._migrate` implements exactly this split, and `tests/replay/test_cli.py::test_a_newer_schema_snapshot_exits_two` plus `tests/replay/test_bundle.py::test_a_missing_migration_step_is_irreproducible_not_a_silent_guess` pin both halves.

### Revision 3 — `bigquery://` is refused for `snapshots_to`

The `state-snapshot-export` requirement specified the message-bus encoding for `snapshots_to` and said nothing about the other schemes the default resolver knows. Left unspecified, `bigquery://` would have resolved to a bare `WriteToBigQuery` handed `(bytes, bytes)` tuples and failed inside a bundle at run time — precisely the class of misconfiguration this project requires to fail at pipeline-construction time with an actionable message. A `StateSnapshot` is an opaque per-key state image with no row layout to invent, so the resolver now refuses that scheme for this field, and the requirement says so. (`otlp://` was already refused for every field but `traces_to`, so it needed no new rule.)

`tests/core/test_transform.py::test_a_bigquery_snapshots_sink_is_refused_at_construction` covers both the resolver and the `AgentConfig` construction path.
