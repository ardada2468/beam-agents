## Why

Correctness invariant 7 promises that breaking proto changes are survivable: "breaking changes require `state_schema_version` bump + lazy migration + golden-blob compat test" ([project.md:48](../../project.md:48)). Today only the first and last words of that promise exist. The three keyed-state blobs carry a `state_schema_version` field — [MemoryBlob](../../../protos/beam_agents.proto:29), [Continuation](../../../protos/beam_agents.proto:179), [LlmCacheBlob](../../../protos/beam_agents.proto:221) — and every writer stamps it `1` ([facade.py:194](../../../src/beam_agents/memory/facade.py:194), [replay_cache.py:203](../../../src/beam_agents/model/replay_cache.py:203), [context.py:691](../../../src/beam_agents/core/context.py:691)). But nothing anywhere *reads* it: the working-memory loader iterates entries without looking at the version ([facade.py:124](../../../src/beam_agents/memory/facade.py:124)), the replay-cache loader likewise ([replay_cache.py:128](../../../src/beam_agents/model/replay_cache.py:128)), and `_AgentDoFn` hands blobs straight from state reads into the activation. A blob stamped `2` — or `7`, from a future binary after a botched rollback — is silently interpreted as if it were `1`.

The golden-blob mechanism is likewise real but single-version: committed v1 baselines under `tests/core/golden/*.bin`, a manual generator ([generate.py:217](../../../tests/core/golden/generate.py:217)), and a compat test asserting field-level decode equality ([test_schema_compat.py:24](../../../tests/core/test_schema_compat.py:24)). It proves additive evolution keeps old bytes decodable. It cannot prove what v2 code does with a v1 blob, because there is no v2, no migration to run, and no corpus layout in which a second version could even live.

**This change is the gate for any future breaking proto change** — the roadmap (C32) marks it exactly so. Until it lands, a breaking change to any state schema is simply forbidden. After it, a breaking change to the versioned state blobs becomes possible, but only through the enforced path: bump the current version constant, register a migration function for every versioned message, and freeze a golden corpus entry for the outgoing version. The enforcement is executable (a CI completeness test that fails on a bump missing either artifact), not prose.

## What Changes

- **New `core/migration.py`: a versioned migration registry.** A module-level `CURRENT_STATE_SCHEMA_VERSION` (equal to `1` at introduction) that the three blob writers derive their stamp from, a registry mapping `(message type, from_version)` to a pure single-step migration function producing `from_version + 1`, and a `migrate_to_current()` that composes the chain, stamps each step, and returns current-version blobs unchanged via an identity fast path. A gap in a chain is a typed hard error, not a skipped step.

- **Lazy migration on first read of keyed state.** `_AgentDoFn` passes every `MEMORY`/`CONTINUATION`/`LLM_CACHE` read through `migrate_to_current()` before any field is interpreted — the two reads in `_start` ([dofn.py:329](../../../src/beam_agents/core/dofn.py:329)), the three in `_resume` ([dofn.py:387](../../../src/beam_agents/core/dofn.py:387), [dofn.py:410](../../../src/beam_agents/core/dofn.py:410)), and the continuation reads in `on_ttl` ([dofn.py:641](../../../src/beam_agents/core/dofn.py:641)) and `on_hitl` ([dofn.py:676](../../../src/beam_agents/core/dofn.py:676)). Migration at read time writes nothing: the migrated value reaches durable state only at the next successful commit, through the existing commit writes ([dofn.py:530](../../../src/beam_agents/core/dofn.py:530)) whose blob builders already stamp the current version — so lazy rewrite falls out of the atomic-commit machinery instead of adding a second write path.

- **Version-from-the-future fails fast.** A blob whose version exceeds `CURRENT_STATE_SCHEMA_VERSION` raises a typed error that fails the bundle before a single field is interpreted — no dead-letter, no state mutation. A wedged key is recoverable by rolling the binary forward; an element processed against misread state is not.

- **A cross-version golden corpus.** `tests/core/golden/` is restructured into per-version directories (`v1/` receives the existing baseline blobs unchanged), the generator gains frozen per-version builders and only ever writes the current version's directory, and the compat test becomes a corpus replay: every blob from every historical version is decoded, run through `migrate_to_current()`, and asserted field-equal to the expected current-version message. Meta-tests pin completeness — every version up to current has a directory, every versioned message has a migration step and a fixture per version — which is what makes the merge gate executable.

- **The documented policy.** `docs/state-migration.md` states what counts as a breaking change, the non-waivable constraint that old bytes must always parse under the current descriptor (never retype or reuse a field number — even a version bump cannot buy that back, because migration runs *after* decode), the bump checklist, and the Dataflow `--update` implications. The unversioned wire messages (`ToolIntent`, `ToolResult`, `TraceEvent`, `AgentEnvelope`, `ActivationErrorRecord`) remain additive-only with no bump escape hatch: they cross service boundaries where a lazy in-pipeline migration cannot reach.

## Capabilities

### New Capabilities

- `state-migration`: the version regime for keyed state — the current-version constant, the migration registry and its chain semantics, the lazy read-path hook in `_AgentDoFn`, fail-fast on future versions, the per-version golden corpus, and the CI-enforced gate on breaking changes.

### Modified Capabilities

- `wire-schemas`: the "Schema evolution is additive and golden-blob guarded" requirement is extended — breaking changes become permitted for the three versioned state blobs, but only via the bump + migration + corpus-entry path, and the golden fixtures move to the per-version corpus layout.
- `proto-coders`: gains a requirement pinning that the coder is migration-invariant — `DeterministicProtoCoder` never migrates on decode and encodes every version as raw deterministic proto bytes, so `--update` state restore stays version-agnostic.

- **New code:** `src/beam_agents/core/migration.py`; `tests/core/test_migration.py` (registry semantics); `tests/core/test_dofn_migration.py` (read-path hook over the fake state handles in `tests/core/_dofn_fakes.py`); per-version corpus directories under `tests/core/golden/`.
- **Modified code:** `core/dofn.py` (the seven keyed-state read sites route through `migrate_to_current()`); `memory/facade.py`, `model/replay_cache.py`, `core/context.py` (writers stamp from the shared constant instead of a literal `1`); `tests/core/golden/generate.py` (per-version builders, current-dir-only output); `tests/core/test_schema_compat.py` (becomes the corpus replay + completeness suite); `tests/core/test_coders.py` (coder migration-invariance); `protos/beam_agents.proto` header comment (names the gate; comment-only, so the committed bindings and drift check are untouched); new `docs/state-migration.md`.
- **CI/build:** no new workflow or make target. The corpus replay and completeness tests run in the unit tier and additionally carry the offline `semantics` marker — `project.md` already names "state compat (golden blobs)" a semantics gate ([project.md:75](../../project.md:75)) — so they ride the required `ci` offline semantics selection; `scripts/check_semantics_partition.py` must still partition cleanly.
- **No wire or public-API change.** Coder bytes, state spec IDs, and `beam_agents/__init__.py` re-exports are all unchanged; at `CURRENT_STATE_SCHEMA_VERSION = 1` every migration is the identity fast path, so a deployed pipeline's behavior is byte-for-byte what it was, and `--update` compatibility is preserved by construction.
- **Gates:** `core/migration.py` and the `dofn.py` edits fall under the `make mutation` gate on `src/beam_agents/core/`; `make lint`, `make type` (`mypy --strict`), `make test-unit`, `make test-semantics-offline`, coverage ratchet, and `uv run pre-commit run --all-files` all apply.
