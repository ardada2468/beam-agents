## Why

vLLM is reachable today only by hand-pointing the OpenAI-compatible provider at a vLLM server's base URL — the C12 spec explicitly promises that "the same client SHALL work against OpenAI, a vLLM OpenAI server, or any compatible gateway by base-URL alone" ([spec.md:24](../add-real-provider-clients/specs/model-providers/spec.md:24)). Workable, but with two gaps.

First, the endpoint ergonomics are wrong for vLLM. `OpenAICompatProvider` requires an `api_key` ([openai_compat.py:83](../../../src/beam_agents/model/openai_compat.py:83)) and defaults its base URL to `https://api.openai.com/v1` ([openai_compat.py:22](../../../src/beam_agents/model/openai_compat.py:22)), while a typical vLLM deployment is unauthenticated and base-URL-mandatory. Today a vLLM user must invent a dummy key and remember to override a default that silently targets OpenAI — a misconfiguration hazard with a real blast radius (real credentials or a wrong endpoint on every activation).

Second — the real gap — there is no way to run the model on the Beam workers themselves. GPU-worker deployments (Dataflow GPU worker pools, self-managed Flink with GPUs) want in-process inference: no separately operated serving fleet, no network hop, GPU utilization driven by the runner's own autoscaling. But a naive in-process engine is an OOM trap: one Beam worker process hosts many DoFn instances, and loading a multi-GB copy of model weights per instance is fatal. `project.md` already sanctions exactly one shape for this — a documented worker-local singleton, "vLLM sidecar via `beam.utils.shared.Shared`" ([project.md:88](../../project.md:88)) — and names both modes on the external-dependencies roster: "vLLM (endpoint or GPU-worker sidecar)" ([project.md:118](../../project.md:118)). This change delivers both modes as first-class providers behind the existing `LLMClient` seam.

## What Changes

- **New `model/vllm.py` with two providers**, each a structural subtype of the `LLMClient` protocol ([spec.md:38](../../specs/model-client/spec.md:38), [client.py:54](../../../src/beam_agents/model/client.py:54)), constructed through the existing `AgentConfig.provider_factory` seam ([transform.py:403](../../../src/beam_agents/core/transform.py:403)) with zero changes to `core/`.
- **Endpoint mode** (`VllmEndpointProvider`): a thin preset that delegates to `OpenAICompatProvider` ([openai_compat.py:73](../../../src/beam_agents/model/openai_compat.py:73)) — base URL **required** (no OpenAI default to mis-hit), API key **optional** (the `Authorization` header is omitted when no key is configured), same non-streaming raw-bytes discipline, same shared HTTP→taxonomy mapper ([_http.py:32](../../../src/beam_agents/model/_http.py:32)), reusing the OpenAI-compatible `Decode` unchanged. No new dependency.
- **GPU-worker sidecar mode** (`VllmSidecarProvider`): an in-process vLLM engine held as **one singleton per worker process**, acquired via `apache_beam.utils.shared.Shared` with a tag derived from the engine configuration. The shared handle owns a dedicated engine thread with its own asyncio loop, so any number of per-DoFn bridge loops submit generation requests to it without loop-affinity violations. A `vllm_sidecar_factory(...)` helper builds the `Shared` handle once at pipeline-construction time so every deserialized DoFn instance in a worker process resolves to the same engine.
- **Health-checked lifecycle in setup**: sidecar provider construction — which `_AgentDoFn.setup` performs via `provider_factory()` ([dofn.py:248](../../../src/beam_agents/core/dofn.py:248)) — runs a bounded readiness probe against the engine and raises on failure, so a worker whose engine cannot load or respond fails fast at setup, before any element is processed. Graceful teardown: engine shutdown runs when the **last** DoFn instance releases its provider reference (`teardown` already nulls it, [dofn.py:253](../../../src/beam_agents/core/dofn.py:253)), never while a sibling instance still shares the engine.
- **Cacheable, decode-compatible response bytes**: the sidecar serializes engine output into a canonical chat-completions-shaped JSON body returned as opaque `LlmResponse` bytes, so the existing `openai_compat.decode` serves both modes and the replay-cache opaque-bytes contract holds. `LlmFacade`'s cache-first path, retry policy, and circuit breaker ([facade.py:208](../../../src/beam_agents/model/facade.py:208)) compose unchanged — a bundle retry on the cached path makes zero engine calls.
- **Engine failures map onto the provider-error taxonomy** ([client.py:63](../../../src/beam_agents/model/client.py:63)): engine queue saturation → `RateLimitError`, engine internal failure → `ServerError`, generation deadline exceeded → `ProviderTimeout` (all retryable), invalid request material rejected by the engine → the non-retryable `ProviderRequestError` ([client.py:89](../../../src/beam_agents/model/client.py:89)). The facade's by-type classification ([facade.py:323](../../../src/beam_agents/model/facade.py:323)) needs no change.
- **A `vllm` extra in `pyproject.toml`** following the effector/langgraph/otlp optional-dependency pattern: `vllm` is imported lazily inside the engine constructor only; `import beam_agents.model` (and endpoint mode) works without the extra; constructing the sidecar without it raises an actionable error.
- **Offline verification via an engine seam**: the sidecar talks to the engine through a narrow internal protocol, so unit tests inject a fake engine — no GPU, no `vllm` install, no docker in the default tier. Real-engine verification is `smoke`-marked and skips without the extra and a GPU.

## Capabilities

### New Capabilities

None. Both modes are implementations of the existing provider seam, not a new contract: the `model-providers` capability introduced by `add-real-provider-clients` is the designated home for provider implementations, their paired `Decode`s, their error-taxonomy mapping, and their test-tier gating, and every requirement here extends that capability additively.

### Modified Capabilities

- `model-providers`: extended (via `## ADDED Requirements` only — no existing requirement's text changes) with the vLLM endpoint preset, the `Shared`-singleton sidecar engine, the health-checked setup lifecycle, chat-completions-shaped cacheable sidecar bytes, the engine-path taxonomy mapping, graceful last-holder engine shutdown, and the `vllm`-extra/offline-seam verification rules.

## Impact

- **Depends on** C05 (`add-fake-llm-provider`, archived 2026-07-22) — the `model-client` seam: the async `LLMClient` protocol, `LlmRequest`/`LlmResponse` opaque-bytes value types, and the retryable `ProviderError`/`RateLimitError`/`ServerError`/`ProviderTimeout` taxonomy both providers raise. **Depends on** C12 (`add-real-provider-clients`, pending) — `OpenAICompatProvider` and its `Decode` (which endpoint mode wraps and sidecar mode's response shape reuses), the shared HTTP→taxonomy mapper in `model/_http.py`, the non-retryable `ProviderRequestError`, the nightly `smoke` tier, and the `model-providers` capability this change extends.
- **New code:** `src/beam_agents/model/vllm.py` (endpoint preset, engine seam, `Shared`-singleton acquisition, health probe, sidecar provider, canonical response serialization, engine-error mapping), `tests/model/test_vllm.py` (fake-engine + mock-transport unit tests), `tests/smoke/test_vllm_sidecar.py` (GPU-gated real-engine smoke).
- **Modified code:** `src/beam_agents/model/__init__.py` (re-exports only). **No `core/` changes**: construction rides the existing `provider_factory` call in `setup` and release rides the existing provider-nulling in `teardown`, so the mutation gate is not in scope.
- **CI/build:** `pyproject.toml` gains the `vllm` optional-dependency extra (pattern of `effector`/`langgraph`/`otlp`) and the lockfile is regenerated; no workflow changes — the default tier stays GPU- and `vllm`-free via the engine seam, and the existing credential/hardware-gated nightly smoke lane absorbs the new smoke test (it skips where no GPU is present).
- **Gates:** `make lint`, `make type` (`mypy --strict`; the lazy `vllm` import is typed behind the seam), `make test-unit` offline with no docker, coverage ratchet at-or-above baseline, `uv run pre-commit run --all-files`, `openspec validate add-vllm-provider --strict`. Mutation gate not applicable (no `core/` file touched).
- **No wire, state, or public-API change:** no proto edits, no `state_schema_version` implication, no new `beam_agents/__init__.py` re-export; the providers surface only through `beam_agents.model` and `provider_factory`, exactly like Anthropic/OpenAI-compatible today.
