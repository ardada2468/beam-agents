## Why

The Dataflow managed service is this project's headline differentiation over Flink Agents ([project.md](../../project.md)), yet there is no deployable artifact: running anything on Dataflow today means cloning the repo, assembling pipeline options by hand, and submitting from a dev machine with a working `uv` environment. Two sibling proposals set up the missing pieces — `add-docs-site` (C24) creates the fraud triage example (keyed transaction events in, `RunAgent` with a suspension/HITL approval flow, intents out) as the repo's canonical runnable pipeline, and `add-yaml-provider` (C36) defines the config-string conventions for selecting a provider and model without writing Python. What neither delivers is packaging: a way for a platform team to launch the fraud pipeline with one `gcloud dataflow flex-template run` (or a console form), supplying only topics, a model string, and an HITL timeout as parameters.

A Dataflow Flex Template is the native shape for that artifact, and the repo already has everything the template needs to stand on: a nightly GCP lane authenticated via Workload Identity Federation and gated on `vars.GCP_PROJECT_ID` ([nightly.yml:34](../../../.github/workflows/nightly.yml:34)), a digest-pinned custom SDK-container precedent with a worked-out protobuf-pinning story ([sdk-harness.Dockerfile:23](../../../docker/sdk-harness.Dockerfile:23)), and a validated `pubsub://<project>/<topic>` URI grammar in the sink resolver ([transform.py:249](../../../src/beam_agents/core/transform.py:249)). Meanwhile the `dataflow` pytest marker is declared and wired into nightly but collects **zero tests** — `make test-dataflow` deliberately tolerates pytest's exit code 5 ([Makefile:63](../../../Makefile:63)). This change gives the lane its first real payload.

## What Changes

- **Add Flex Template packaging for the fraud example** under `examples/fraud_triage_dataflow/` (colocated with the C24 example): a `Dockerfile` building one dual-purpose image (template launcher **and** Beam SDK harness container, following the pinning discipline of [sdk-harness.Dockerfile:23](../../../docker/sdk-harness.Dockerfile:23)), a `metadata.json` declaring the template parameter surface with regex validation, and a launcher module `launch.py` that maps template parameters onto the fraud pipeline's `AgentConfig`/`HitlPolicy` and runs it.
- **Parameterize the pipeline**, at minimum: `input_topic` and `approvals_topic` (Pub/Sub reads), `output_topic` and `intents_topic` (writes; intents via the existing `intents_to` sink URI, [transform.py:417](../../../src/beam_agents/core/transform.py:417)), optional `errors_to`/`traces_to` sinks, `model` (a single provider+model config string following `add-yaml-provider`'s conventions), and `hitl_timeout_ms` (maps to `HitlPolicy.timeout_ms`, [hitl.py:145](../../../src/beam_agents/hitl.py:145)). All topic parameters use the sink resolver's `pubsub://<project>/<topic>` grammar — one grammar everywhere.
- **Handle provider API keys via Secret Manager, never as template parameters.** The template accepts an optional Secret Manager *resource name* (`projects/*/secrets/*/versions/*`); workers resolve the value at provider construction using the job's service-account credentials. Secret values never appear in launch parameters, job metadata, or logs. The FakeLLM path needs no secret, so the parameter is optional.
- **Add the build/publish workflow**: the nightly `dataflow` job (already WIF-authenticated, gated on `vars.GCP_PROJECT_ID != ''`, [nightly.yml:37](../../../.github/workflows/nightly.yml:37)) gains steps that build the image, push it to Artifact Registry tagged by git SHA, and run `gcloud dataflow flex-template build` to produce the template spec in GCS.
- **Add the smoke validation path**: the repo's first `-m dataflow` test launches the freshly built template with FakeLLM-oriented parameters, asserts the job reaches `JOB_STATE_RUNNING` (proving the launcher, parameter surface, and worker container all resolve), then cancels it. This runs in the existing nightly `test-dataflow` step; no Makefile change is needed.

## Impact

- **Depends on** sibling proposals `add-docs-site` (C24 — creates `examples/fraud/`, the pipeline this template packages; today no `examples/` directory exists) and `add-yaml-provider` (C36 — defines the provider/model config-string grammar the `model` parameter reuses, so YAML pipelines and the template share one model-selection vocabulary). This change must land after both; its launcher imports the fraud pipeline's assembly function rather than duplicating it.
- **New code:** `examples/fraud_triage_dataflow/Dockerfile`, `examples/fraud_triage_dataflow/metadata.json`, `examples/fraud_triage_dataflow/launch.py` (+ a short `README.md` for the directory); `tests/examples/test_flex_template_metadata.py` and `tests/examples/test_flex_template_launcher.py` (offline unit tests); `tests/dataflow/test_flex_template_launch.py` (the first `-m dataflow` test). No changes under `src/beam_agents/` — the runtime stays a library; Secret Manager resolution lives in the example's launcher, and `google-cloud-secret-manager` is baked into the template image only, not added to the package's dependencies.
- **Modified code:** none in `src/`. `docker/README.md` gains a pointer distinguishing the local-stack SDK harness image from the template image.
- **CI/build:** `.github/workflows/nightly.yml`'s `dataflow` job ([nightly.yml:34](../../../.github/workflows/nightly.yml:34)) gains image build, Artifact Registry push, and `gcloud dataflow flex-template build` steps ahead of the existing `make test-dataflow` step; the `skip-notice` job ([nightly.yml:64](../../../.github/workflows/nightly.yml:64)) continues to cover forks without GCP. `make test-dataflow` ([Makefile:63](../../../Makefile:63)) is unchanged — it already selects `-m dataflow`, and once the launch test exists its exit-5 tolerance stops being load-bearing.
- **Gates:** offline metadata/launcher tests ride `make test-unit` and the coverage ratchet; the launch test is nightly-only per the `dataflow` tier contract ([project.md](../../project.md), testing tiers). `make lint`, `make type`, and `openspec validate add-dataflow-flex-template --strict` must pass.
