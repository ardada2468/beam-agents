## Why

`.traces` is a wired output tag carrying almost nothing. The runtime emits three kinds of `TraceEvent` today — `ACTIVATION_START`, `ACTIVATION_END`, and an `LLM_CALL` — and **not one of them sets `trace_id`, `span_id`, or `parent_span_id`**. Every event is an unparented orphan, so nothing downstream can reconstruct "what did this activation do", let alone join a pipeline-side activation to the effector execution it caused. `TOOL_CALL`, `INTENT_EMITTED`, and `ERROR` are declared in the schema and never produced at all; the timer paths (HITL timeout, escalation, TTL-wiped suspension) emit nothing on `.traces`; and the two context surfaces disagree — the model facade stages six OTel-shaped attributes while `ActivationContext.call_model` stages two, with **no token counts on any cached call**.

That last gap is the expensive one. A cache hit re-serves a stored provider response whose usage numbers are sitting right there in the cached bytes; reporting them as absent (`ActivationContext`) or as literal `0` (the facade's error paths) turns the replay cache — the feature that makes bundle retries cheap — into a hole in cost accounting. And nothing on the wire carries a trace identifier out of the pipeline: `ToolIntent` has no `trace_id`, so the effector's execution of an intent can never be stitched back to the activation that requested it.

## What Changes

- **Add `observability/traces.py`: deterministic trace and span identity.** `trace_id = uuid5(NS, key|seq)` (16 bytes) and `span_id = uuid5(NS, key|seq|<role>|<index>)[:8]` (8 bytes) — pure functions of activation scope, computed exactly like `intent_id_for` and reading no clock or counter. A replayed bundle produces byte-identical trace events, and the ids are stable enough for downstream dedup.
- **One trace per `(key, seq)`, spanning suspension.** A resumed activation shares its suspended activation's `seq`, so it recomputes the *same* `trace_id` with no correlation state on the wire. The suspend/resume cycle is one trace by construction; each activation attempt gets its own span under the root activation span.
- **Correlation is stamped at the staging boundary, not by producers.** `stage_trace_event` on both contexts fills `trace_id`, `span_id`, and `parent_span_id` on any event that arrives without them. The model facade, the tool runner, and the loop driver keep emitting plain events and need no new parameters; every producer is correlated for free.
- **Emit the child events the schema already declares.** `TOOL_CALL` from `AgentContext.run_tool`, `INTENT_EMITTED` from both contexts' `_stage_intent` (and from `_escalate`, which mints an intent outside any activation), `ERROR` from every DoFn failure route, and a new `SUSPENDED` event carrying the deadline, adapter, and pending intent ids.
- **Truthful token counts on cache hits.** `ActivationContext` gains the injected provider `Decode` the facade already takes, so a cache-hit trace reports the *stored* response's usage. Usage attributes that are genuinely unknown (a call that failed before any response, or a context with no `decode` configured) are **omitted rather than written as `0`** — an absent attribute means unknown, a present one is true. `beam_agents.billed` distinguishes a cache hit's real-but-already-paid-for tokens from a provider call's new spend, so aggregation over `.traces` neither loses nor double-counts.
- **`trace_id` on the wire.** Additive `bytes trace_id = 11` on `ToolIntent`, populated from the activation's trace at staging time. The effector can open a child span under the pipeline's trace. `ToolResult` deliberately gets no such field: a resume recomputes the trace id from `(key, seq)`.
- **Failure routes produce traces.** The DoFn synthesizes a self-contained `ERROR` event — from the key, seq, and reason it already holds — on `activation_timeout`, `activation_error`, `orphaned_result`, `hitl_timeout`, and `ttl_wiped_suspension`, and emits it on `.traces` beside the existing `.errors` record. Staged effects of a failed activation stay discarded (correctness invariant 1 is untouched); the synthesized event is derived from the DoFn's own knowledge, not from the rolled-back context.
- **`.traces` reaches its configured sink.** `.traces` currently carries `TraceEvent` protos into a raw `WriteToKafka`/`WriteToPubSub`/`WriteToBigQuery`, none of which accept a proto message — so a configured `traces_to` fails at runtime today. `DefaultSinkResolver` gains a serialization step for `traces_to`, mirroring how `intents_to` already special-cases its writer.

## Capabilities

### New Capabilities
- `trace-events`: deterministic trace/span identity, the activation span and its `LLM_CALL`/`TOOL_CALL`/`INTENT_EMITTED`/`SUSPENDED`/`ERROR` child events, the OTel GenAI attribute vocabulary, staging-boundary correlation, `trace_id` propagation into `ToolIntent`, and delivery of `.traces` to a configured sink.

### Modified Capabilities
- `wire-schemas`: `ToolIntent` gains `trace_id` (bytes, field 11); `TraceEvent.EventType` gains `SUSPENDED = 7`. Both additive under `state_schema_version = 1`.
- `model-facade`: per-call trace emission carries correlation ids stamped by the staging sink, reports a cache hit's truthful decoded usage, and omits usage attributes it does not know instead of reporting them as zero.

## Impact

- **New code:** `observability/__init__.py`, `observability/traces.py` (id derivation, `ActivationTrace`, attribute constants), `observability/exporters.py` (trace-event serialization for the sink path). New `trace-events` spec. (`observability/metrics.py` belongs to the `runtime-metrics` capability, merged from `main` during implementation; this change's `TOOL_CALL` tracing rides its `ActivationContext.run_tool`.)
- **Modified code:** `protos/beam_agents.proto` + regenerated `_pb2.py`; `core/context.py` (both contexts: stamping sink, `INTENT_EMITTED`, `TOOL_CALL`, decoded cache-hit usage); `core/loop.py` (activation span, `SUSPENDED`); `core/dofn.py` (`ERROR` events on the five failure routes, `INTENT_EMITTED` on escalation); `core/transform.py` (traces sink serialization); `model/facade.py` (attribute vocabulary, omit-unknown usage).
- **Wire/state change:** additive only — old `ToolIntent` blobs decode with an empty `trace_id`, and readers that do not know `SUSPENDED` see an unrecognized enum number. No `state_schema_version` bump. `PENDING` BagState holds `ToolIntent`, so the golden-blob compat suite needs a populated-`trace_id` golden alongside the existing one, which must keep parsing unchanged.
- **Behavior change:** `.traces` volume rises from ~3 events per activation to ~3 + one per model call, tool call, and intent. Traces are emitted at-least-once (a retried bundle re-emits byte-identical events); downstream dedup is by `(trace_id, span_id, event_type)`.
- **Non-goal, called out because its absence is visible:** span *durations*. Every event takes `start_ms`/`end_ms` from the injected activation clock, so spans have zero width. Measuring real elapsed time needs a wall clock inside the hot path, which would weaken `model-facade`'s standing "MUST NOT read wall-clock time" requirement. Latency belongs to Beam metrics — the `runtime-metrics` capability, merged from `main` during implementation — so the trace stream answers *what happened, in what order, at what token cost* while the runner dashboard answers *how long it took*.
- **Tests:** id-determinism and collision unit tests; parent/child linkage across suspend→resume; a cache-hit usage test asserting the stored response's real counts (not zeros); an intent-`trace_id` propagation test through the DoFn commit; failure-route trace tests for all five reasons; golden-blob compat for the widened `ToolIntent`; a `TestStream` assertion that `.traces` is populated end to end.
- **Mutation gate:** `core/dofn.py` and `core/context.py` are under the gate; new branches there move `mutation-baseline.toml`'s ceilings and must be re-checked after implementation. In the event this was the largest single effect of the change: the fake-handle failure-route tests drive `process()` and sit *inside* the mutation selection, where previously only the deselected Beam-pipeline suites reached `process`/`_start`/`_resume`/`_commit`. That moved 264 `dofn.py` mutants out of the "no tests" bucket, and `tests/core/test_dofn_commit.py` was added to kill them — element routing by payload variant, the exact value written to each state spec, the commit order, the SEQ increment, both timer arms, and every argument forwarded down to the activation. `dofn.py`'s ceiling drops 267 → 3; `transform.py`'s rises 198 → 240 for the new `_WriteTraces` code its deselected suite owns.
