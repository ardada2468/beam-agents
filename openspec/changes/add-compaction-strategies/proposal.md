## Why

The compaction seam exists end to end, and nothing real has ever run in it. The `Compactor` protocol shipped with the memory facade ([facade.py:58](../../../src/beam_agents/memory/facade.py:58)), and the facade invokes it at the soft-cap crossing ([facade.py:256](../../../src/beam_agents/memory/facade.py:256)) and once before hard-cap rejection ([facade.py:214](../../../src/beam_agents/memory/facade.py:214)). `ActivationContext` accepts a `compactor` and hands it to the facade ([context.py:392](../../../src/beam_agents/core/context.py:392), [context.py:410](../../../src/beam_agents/core/context.py:410)), and `run_activation` threads it through ([loop.py:162](../../../src/beam_agents/core/loop.py:162)). But `_AgentDoFn._activate` never passes one ([dofn.py:483](../../../src/beam_agents/core/dofn.py:483)) and `AgentConfig` has no field for it ([transform.py:395](../../../src/beam_agents/core/transform.py:395)) — so in every shipped pipeline the parameter is dead, `compactor` is `None`, and the 1 MiB hard cap's only behavior is `MemoryOverflow` → activation failure → dead letter. A key whose agent keeps appending marches monotonically toward guaranteed permanent failure, one write past the cap.

Two further gaps follow once compaction gets real:

1. **Summarization needs the LLM, and a naive summarizer breaks the runtime's core promise.** Any implementation that calls the provider outside the activation — from a timer callback, a side transform, or a raw client — makes a call that is not in the replay cache, not staged, and not keyed by `(key, seq)`. A retried bundle then re-calls the provider, may get different bytes, and commits a different `MemoryBlob` than the first attempt would have: a direct violation of correctness invariants 1 and 3. Where the summarization runs is the whole design problem, not an implementation detail.

2. **TTL expiry destroys working memory instead of demoting it.** `on_ttl` wipes all five state specs unconditionally ([dofn.py:660](../../../src/beam_agents/core/dofn.py:660)) — correct GC, but oblivion is the only exit. With the long-term tier from `add-longterm-memory-stores` (C29) in place, expiring working memory finally has somewhere to go; the hook to send it there is missing, and the TTL fire is a hostile place to add one (no activation context, no event, a watermark-domain timer).

## What Changes

- **New `src/beam_agents/memory/compaction.py`** — the module map's designated `memory/` "compaction" slot — with two strategies split by *where they are allowed to run* (see design D1):
  - **`DropOldestCompactor`**: a synchronous, LLM-free `Compactor` that deletes entries in LRU order until `size_bytes` is at or below a target (default: half the hard cap, for hysteresis below the 75% soft cap), never touching configured protected key prefixes (default includes the LangGraph checkpoint namespace `__langgraph__/`, which compactors are already documented as forbidden to evict — [checkpoint.py:26](../../../src/beam_agents/adapters/langgraph/checkpoint.py:26)). It becomes the **wired default**: `AgentConfig` gains a `compactor` field defaulting to it, and `_AgentDoFn` finally passes the value into `run_activation`, closing the dead parameter.
  - **`SummarizeCompactor`**: an asynchronous strategy the *loop driver* invokes **inside the activation**, after the agent returns and before the outcome is folded into `ActivationResult`, whenever staged `memory.size_bytes` has reached a trigger threshold (default: the soft cap). Its LLM calls go exclusively through `ctx.call_model` — the same cache-first path the agent uses ([context.py:469](../../../src/beam_agents/core/context.py:469)) — so every call is keyed by `sha256(..., key, seq)` ([replay_cache.py:73](../../../src/beam_agents/model/replay_cache.py:73)), staged in the replay cache, committed atomically with the bundle, and **replayed from cache with zero provider calls on bundle retry**. It folds the oldest items of configured source rings into one scalar summary entry, keeping the newest items verbatim. The caller supplies the request builder and response extractor; the runtime owns only lifecycle and determinism (no prompt templating in the runtime — design D5).
- **`Memory` gains a read-only enumeration surface** so a compactor can actually be written against the guarded API: `keys()` returning key names in LRU order (least-recently-used first) and `entry_size(key)` returning an entry's stored encoded size — both explicitly **not** re-stamping access order and not setting `dirty`, because a compactor that perturbs LRU order while iterating it would evict the wrong entries. This is an additive requirement on the existing `memory-facade` capability; no existing requirement changes.
- **An `on_expire` flush hook from working memory to the long-term tier.** `AgentConfig` gains `on_expire` (default `None` — today's wipe-only behavior is unchanged). When configured together with the long-term `MemoryStore` from C29, `on_ttl` reads the final `MemoryBlob` and the key's committed `seq` *before* wiping, and performs one idempotent upsert keyed by `(entity_key, seq)` through the store — the exact side-effect carve-out invariant 5 documents — bounded on the async bridge; the wipe proceeds only after the flush succeeds, and a flush failure fails the timer bundle so the runner retries it (retry-safe by idempotency). The tension of running any effect at TTL fire — no activation context exists there — gets its own design decision (D4), including why the flush is not routed through the last activation or the intent/effector path.

## Capabilities

### New Capabilities

- `memory-compaction`: the concrete compaction strategies and their execution contracts — `DropOldestCompactor` as the wired default for the facade's synchronous cap-enforcement hook, `SummarizeCompactor` running inside the activation with replay-cached LLM calls, and the `on_expire` flush of expiring working memory to the long-term tier. The `AgentConfig`/DoFn/loop-driver wiring requirements are stated here rather than by modifying the (unarchived) runtime changes' specs, following the `add-runtime-metrics` precedent.

### Modified Capabilities

- `memory-facade`: gains one ADDED requirement — the LRU-ordered, access-order-preserving enumeration surface (`keys()` / `entry_size()`) that compaction strategies iterate. Every existing requirement, including the `Compactor` protocol contract and the check→compact→reject cap order, is untouched.

## Impact

- **Depends on**: `add-longterm-memory-stores` (C29, a sibling proposal in this batch) for the `MemoryStore` ABC, the configured long-term tier, and the `(key, seq)`-keyed idempotent upsert contract the `on_expire` flush writes through — the flush tasks are sequenced after it; and the archived `add-memory-facade` (C03, `openspec/changes/archive/2026-07-23-add-memory-facade/`) for the `Compactor` protocol, ring buffers, and cap machinery this change puts to work.
- **New code:** `src/beam_agents/memory/compaction.py`; `tests/memory/test_compaction.py` (drop-oldest + enumeration), `tests/core/test_loop_summarize.py` (driver invocation, atomic failure), `tests/core/test_dofn_expire.py` (fake-handle `on_ttl` flush tests).
- **Modified code:** `src/beam_agents/memory/facade.py` (`keys()`/`entry_size()`), `src/beam_agents/memory/__init__.py` (exports), `src/beam_agents/core/transform.py` (`AgentConfig.compactor` / `summarizer` / `on_expire`), `src/beam_agents/core/dofn.py` (pass the compactor into `run_activation`; flush-then-wipe in `on_ttl`), `src/beam_agents/core/loop.py` (summarizer invocation point inside the failure wrap), `tests/semantics/test_retry_determinism.py` (extended with a summarizing agent). No proto change, no `state_schema_version` move, no golden-blob movement: strategies mutate state only through the existing facades, and the flush writes an external store, not keyed state.
- **CI/build:** none — no new dependencies, no workflow or make-target changes; the new tests ride the existing unit and offline-semantics selections.
- **Behavior change:** with the default compactor wired, a hard-cap-crossing write that previously raised `MemoryOverflow` (dead-lettering the activation) now succeeds after LRU eviction. Pipelines that relied on overflow-as-failure set `compactor=None` (see Migration Plan).
- **Gates:** `core/dofn.py`, `core/loop.py`, and `core/transform.py` are under the mutation gate — `mutation-baseline.toml` ceilings re-checked and any move documented, per the `add-runtime-metrics` precedent. Coverage ratchet at or above baseline. The retry-determinism semantics gate must pass with the summarizing agent added (zero extra FakeLLM calls, byte-identical committed blobs), and the `ttl_expiry` conformance scenario must pass unchanged with `on_expire` unset.
