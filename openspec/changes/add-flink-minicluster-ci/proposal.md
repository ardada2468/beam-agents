## Why

The Flink mini-cluster already carries the repo's two heaviest release gates — the effectively-once e2e gate (`make test-semantics`) and the adapter conformance matrix's Flink leg (`make test-conformance-flink`) — but it does so inside one monolithic CI job. [integration.yml:16](../../../.github/workflows/integration.yml:16) defines a single `integration` job that brings up the whole compose stack ([integration.yml:38](../../../.github/workflows/integration.yml:38)) and runs `make test-integration`, `make test-semantics`, and `make test-conformance-flink` sequentially under one 60-minute budget ([integration.yml:20](../../../.github/workflows/integration.yml:20)). Four consequences, each observable today:

1. **No job-level failure attribution or parallelism.** A red `make test-integration` (Kafka/Redis/emulator client tests, no Flink involved) aborts the job before the Flink gates ever run, and the Flink gates serialize behind it; re-running a flaky Flink recovery scenario re-pays the whole job. The step comments in [integration.yml:46](../../../.github/workflows/integration.yml:46) and [Makefile:45](../../../Makefile:45) go to lengths to keep *step*-level failures distinguishable — but the job boundary, timeout budget, and re-run unit are still shared.
2. **Every PR pays the full Flink stack for tests that never touch it.** No `integration and not semantics` test uses Flink (verified: `tests/actions/test_write_intents_integration.py` and `tests/effector/test_*` reference only Kafka, Redis, and the GCP emulators; [compose.yaml:120](../../../docker/compose.yaml:120) records that nothing but the Beam-on-Flink gates submits a job), yet `make compose-up` ([Makefile:78](../../../Makefile:78)) pulls the Flink/jobserver images and builds the SDK-harness image before any of them can run.
3. **A red Flink run destroys its own evidence.** `make compose-down` runs `if: always()` ([integration.yml:51](../../../.github/workflows/integration.yml:51)), removing the containers — and with them the JobManager/TaskManager/jobserver/harness logs — before anyone can read them. The harness already writes diagnostic treasure (TaskManager thread dumps via [`capture_tm_thread_dump`](../../../tests/semantics/_flink_stack.py:181), per-vertex stall summaries via [`job_vertex_summary`](../../../tests/semantics/_flink_stack.py:164)), but the workflow uploads nothing: there is no `actions/upload-artifact` step anywhere in the repo's CI.
4. **The marker partition check has a path-scope blind spot.** `scripts/check_semantics_partition.py` proves the offline and docker *marker* selections partition the semantics tier ([check_semantics_partition.py:51](../../../scripts/check_semantics_partition.py:51)) — but the two docker-lane make targets are additionally **path-scoped** (`tests/semantics` at [Makefile:50](../../../Makefile:50), `tests/conformance` at [Makefile:55](../../../Makefile:55)). A `semantics and integration` test added anywhere else (say `tests/effector/`) would be counted as docker-lane by the script yet executed by neither make target: green partition check, gate never runs. Nothing guards that today.

This change formalizes the Flink mini-cluster lane as a dedicated CI job with its own budget, caching, and failure diagnostics, and closes the coverage gap so the markers the job exists to run cannot silently escape it. It extends the wiring that C16 and C22 landed; it does not re-propose or duplicate their gates.

## What Changes

- **Split `integration.yml` into two jobs.** The existing `integration` job keeps its name (its status-check context is required on `main`; renaming it would strand branch protection) and shrinks to the non-Flink tier: a new `make compose-up-core` brings up only Redpanda, Redis, and the two GCP emulators (explicit service list; `docker/compose.yaml` unchanged), then `make test-integration` runs, with a ~20-minute budget. A new **`flink-minicluster` job** owns the Beam-on-Flink lane: full `make compose-up` (unchanged target — the SDK-harness `--build` semantics and the repo-scaffolding contract stay intact), then `make test-semantics` and `make test-conformance-flink` as separate steps exactly as today, under its own timeout. The two jobs run in parallel; a conformance red no longer blocks or re-runs the Kafka/Redis integration tests, and vice versa.
- **Cache what the Flink job rebuilds every run.** Reorder [sdk-harness.Dockerfile](../../../docker/sdk-harness.Dockerfile) so the third-party `pip install` layer (protobuf pin, httpx, pydantic, aiokafka, langgraph — the slow, network-bound part) precedes the `COPY src` (`/src` is copied at [sdk-harness.Dockerfile:30](../../../docker/sdk-harness.Dockerfile:30) *before* the combined install at [sdk-harness.Dockerfile:36](../../../docker/sdk-harness.Dockerfile:36), so today any `src/` edit re-downloads everything). The `flink-minicluster` job pre-builds the image through buildx with a GitHub-Actions layer cache (`type=gha`) and loads it, so `make compose-up` (invoked with the build flag suppressed in CI only, where the preceding step just built from the same checkout) starts a current image without a cold rebuild. Base images stay pulled-by-digest, deliberately uncached (see design). `uv` dependency caching via `setup-uv` is already in place and carries over to both jobs.
- **Upload Flink diagnostics on failure, before teardown.** A new `make compose-logs` target collects per-service `docker compose logs` plus the harness's on-disk diagnostics (`docker/e2e-spool/*-tm-threads.txt` thread dumps — spool segment files excluded) and Flink REST snapshots (`/jobs/overview`, `/taskmanagers`) into a directory; the `flink-minicluster` job runs it `if: failure()` and uploads the directory with `actions/upload-artifact` *before* the `if: always()` `make compose-down` removes the containers. The base job gets the same treatment for its (much smaller) service logs.
- **Close the path-scope coverage gap.** Extend `scripts/check_semantics_partition.py`: in addition to the existing marker-partition assertions, it collects the two path-scoped selections the docker make targets actually run and fails if their union differs from the repo-wide `semantics and integration` selection (or if either is empty). The set algebra moves into a pure, unit-testable function; the script keeps running in the existing required `ci` step ([ci.yml:52](../../../.github/workflows/ci.yml:52)) — no new workflow.
- **Update `docs/ci.md`** — the workflow map row for `integration.yml` ([ci.md:9](../../../docs/ci.md:9)) becomes two rows, and the effectively-once-gate section's "runs in the `integration` workflow" prose names the `flink-minicluster` job. `docker/README.md`'s "one test" claim for the jobserver ([README.md:24](../../../docker/README.md:24)) is corrected to name both Flink-backed suites while touching that file.
- **Not changing:** the make targets' pytest selections, the compose service definitions, the gates themselves, the offline semantics lane, `quality.yml`/`nightly.yml`, or any test under `tests/`. `make compose-up` keeps `--wait --build` for local use.

## Capabilities

### New Capabilities

- `flink-minicluster-ci`: the CI contract for the Flink mini-cluster lane — a dedicated job that runs the docker-backed `semantics`/`integration` marker selections separately from the base integration job, the layer-cache discipline for the SDK-harness image, the failure-time capture and upload of Flink logs and diagnostics before teardown, and the extended partition check guaranteeing no docker-backed semantics test can escape the lane's path-scoped make targets.

### Modified Capabilities

None. The `effectively-once-e2e-gate` and `adapter-conformance-matrix` CI-wiring requirements are consumed unchanged and remain satisfied to the letter: the e2e gate is still "selected by the docker semantics selection (`-m "semantics and integration"`) in the integration workflow", and the conformance Flink leg still runs as its own `make test-conformance-flink` step distinct from `make test-semantics` — this change moves both steps into a dedicated job of the same workflow without altering their selections or distinguishability. `repo-scaffolding`'s workflows requirement also still holds verbatim (`integration.yml` continues to invoke `make compose-up`, `make test-integration`, and `make test-semantics` on `ubuntu-latest`); deliberately not amending it also avoids stacking a third concurrent delta on the requirement that `drop-macos-ci-matrix-leg` and `enforce-mutation-gate-on-core` both already rewrite (their proposals document the full-body-replacement collision hazard).

## Impact

- **Depends on** C16 (`add-effectively-once-e2e-gate`) and C22 (`add-adapter-conformance-matrix`) — the two Flink-backed gates and their make targets/steps ([Makefile:49](../../../Makefile:49), [Makefile:54](../../../Makefile:54)) are what the dedicated job runs, and the harness diagnostics this change uploads are produced by their shared stack machinery ([tests/semantics/_flink_stack.py:42](../../../tests/semantics/_flink_stack.py:42)).
- **New code:** `tests/scripts/test_semantics_partition.py` (unit tests for the extracted partition/coverage set algebra); no `src/beam_agents/` changes of any kind.
- **Modified code:** `scripts/check_semantics_partition.py` (pure-function extraction + path-scoped coverage assertions), `docker/sdk-harness.Dockerfile` (layer reorder only — final image contents and its build-time import self-check unchanged), `Makefile` (new `compose-up-core`, `compose-logs`, `harness-build` targets; `compose-up` gains an overridable flags variable defaulting to today's `--wait --build`), `docs/ci.md`, `docker/README.md`.
- **CI/build:** `.github/workflows/integration.yml` restructured into `integration` + `flink-minicluster` jobs (same triggers, same workflow-level concurrency group); buildx/GHA-cache steps and `if: failure()` artifact-upload steps added. **Branch protection:** `main` currently requires the `integration` context by exact name (recorded in `drop-macos-ci-matrix-leg`'s pre-flight finding) — the base job keeps that name, and `flink-minicluster` must be *added* to the required contexts in the same window the PR merges, an operational step called out in tasks.
- **Gates:** no gate weakens. The e2e gate and conformance Flink leg run with identical selections in the new job; the partition check gets strictly stronger (path-scope coverage on top of marker partition); `make test-unit` coverage is unaffected (scripts are outside `--cov=beam_agents`); no `core/` module is touched, so the mutation gate is not in play.
