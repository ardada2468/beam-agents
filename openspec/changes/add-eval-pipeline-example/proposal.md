## Why

The runtime now tells the whole truth about what an agent *did*: every activation emits deterministic, fully-correlated `TraceEvent`s ([traces.py:83](../../../src/beam_agents/observability/traces.py:83)), and `add-trace-exporters` gave that stream real exits — keyed deterministic bytes on Kafka/Pub/Sub ([exporters.py:57](../../../src/beam_agents/observability/exporters.py:57)), a self-provisioning BigQuery table ([exporters.py:32](../../../src/beam_agents/observability/exporters.py:32)), and best-effort OTLP ([otlp.py:395](../../../src/beam_agents/observability/otlp.py:395)). What nothing tells anyone is whether the agent decided *well*. For the target workloads (fraud triage, anomaly response), quality signals are business outcomes — a chargeback confirmed, an alert acknowledged as real, a customer escalation — that arrive on separate streams, minutes to days after the activation they judge. Closing that loop is a second Beam pipeline: join traces with outcomes, score the joined record with an LLM-as-judge, aggregate per scenario. Every team deploying `RunAgent` will need one, and the design has real traps — outcome lag makes naive windowed joins wrong, at-least-once trace delivery double-counts under careless aggregation, and unversioned judge prompts silently invalidate every score trend the pipeline exists to produce.

There is also an unproved claim on the books. The errors output's "consumable by an ordinary downstream pipeline with nothing but public bindings" promise is held by a doc-contract test ([test_failure_streak_alarm.py](../../../tests/examples/test_failure_streak_alarm.py) ↔ [docs/errors.md](../../../docs/errors.md)); the trace stream makes the same promise — [docs/traces.md](../../../docs/traces.md) calls `.traces` "a `PCollection[TraceEvent]` you can consume yourself" — and no test holds it. This change is that example and that test, in one doc-contract pair.

## What Changes

- **A documented continuous-evaluation example pipeline** on the examples surface established by sibling change `add-docs-site` (C24): a standalone downstream Beam pipeline that (1) reads exported trace bytes from the Kafka traces topic and decodes them with the public proto bindings, (2) joins per-activation trace summaries with business outcomes in a stateful DoFn keyed by `(entity_key, seq)` — the same pair `trace_id_for` derives trace identity from — with an event-time evaluation deadline instead of a lag-bounded window, (3) scores joined records with an LLM-as-judge stage: a plain `DoFn` calling a provider through the `LLMClient` seam ([client.py:54](../../../src/beam_agents/model/client.py:54)) with an explicitly versioned judge prompt and a fail-closed verdict parse, and (4) emits per-record verdict rows plus fixed-window per-scenario aggregates to BigQuery, with the drill-down SQL documented beside the table layout, mirroring [docs/traces.md](../../../docs/traces.md).
- **A doc-contract test** (`tests/examples/test_continuous_eval.py`) holding the example verbatim, following the `docs/errors.md` pattern: the pipeline stages are copied from the doc unchanged, fed trace bytes produced by the runtime's own encoder ([exporters.py:57](../../../src/beam_agents/observability/exporters.py:57)), and the judge runs on `FakeLLM` ([fake.py:128](../../../src/beam_agents/model/fake.py:128)) — fully offline, no docker, no network.
- **Honest failure surfaces in the example itself:** an outcome with no live activation state routes to an `orphaned_outcomes` output (the downstream mirror of the runtime's `orphaned_result` discipline), an activation whose deadline fires without an outcome emits an explicit `no_outcome` record rather than vanishing, and an unparseable judge verdict routes to `judge_errors` instead of fabricating a score.
- **No runtime changes.** The example consumes only public bindings and documented encodings; `src/`, `protos/`, and existing capabilities are untouched.
