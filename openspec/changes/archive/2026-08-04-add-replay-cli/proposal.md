## Why

The runtime's central promise — deterministic replay — currently stops at the runner's edge. Every ingredient of an offline re-run already exists: [`run_activation`](../../../src/beam_agents/core/loop.py:149) is a pure async driver that takes `(agent, memory_blob, cache_blob, event, ...)` and reads no Beam state and no wall clock; the [`ReplayCache`](../../../src/beam_agents/model/replay_cache.py:112) holds every LLM response keyed by [`compute_cache_key`](../../../src/beam_agents/model/replay_cache.py:73) so a re-walk of the same path needs zero provider calls; and `.traces` carries a byte-deterministic [`TraceEvent`](../../../protos/beam_agents.proto:94) record of what the activation did, with identifiers derived by [`trace_id_for`](../../../src/beam_agents/observability/traces.py:83) as pure functions of `(entity_key, seq)`. But no tool composes them. When an operator asks "why did the activation for key K at seq 7 emit that intent", the only options today are reading trace rows in BigQuery or attaching a debugger to a live pipeline. There is no way to get the keyed-state blobs for one entity out of a running pipeline, and no harness that reconstructs the activation locally and re-runs it against the cached responses.

Two gaps block this. First, **state export**: `MEMORY`, `CONTINUATION`, `LLM_CACHE`, and `PENDING` live in runner-managed keyed state ([dofn.py:199](../../../src/beam_agents/core/dofn.py:199)), and no portable API reads them from outside — Flink's State Processor API is JVM-only, Dataflow snapshots are opaque, and DirectRunner state dies with the process. Second, **a replay harness**: nothing loads a trace plus a state image, rebuilds the `run_activation` arguments, substitutes a provider that serves only from the replay cache, and diffs the re-run against the traced outcome.

## What Changes

- **A `StateSnapshot` export mechanism that rides the pipeline itself.** [`AgentEnvelope`](../../../protos/beam_agents.proto:130) gains a fourth `oneof payload` variant, `export_request`: an operator publishes it to the events topic keyed by the target `entity_key`, and — because Beam serializes elements per key — the stateful DoFn handles it at a consistent point in the key's stream, reads its four state blobs plus the `SEQ` counter **without mutating anything** (no `SEQ` increment, no activation), and emits one `StateSnapshot` proto on a new `.snapshots` tagged output. `AgentConfig.snapshots_to` resolves a sink for it exactly as `traces_to` does. This is the only portable design; savepoint readers and continuous state mirroring are rejected in the design doc with the runner-specific reasons.
- **A new `StateSnapshot` wire message** carrying `state_schema_version`, `entity_key`, the current `seq`, the export request's deterministic `event_time_ms`, and the four blobs (`MemoryBlob`, `LlmCacheBlob`, `Continuation` when suspended, pending `ToolIntent`s). Additive proto change only.
- **A `beam-agents-replay` console script** (new `beam_agents/replay/` package, entry point following the [`beam-agents-effector`](../../../pyproject.toml:48) pattern in [`effector/__main__.py`](../../../src/beam_agents/effector/__main__.py:60)). It loads a `StateSnapshot` file and a `TraceEvent` stream, imports the agent (and optionally the tool registry) by `module:attribute` path, reconstructs the `run_activation` inputs — `entity_key`, `seq`, the triggering event or resume payload (supplied from the durable events topic; traces deliberately carry no payloads), `now_ms` recovered from the traced `ACTIVATION_START`'s `start_ms`, `step_index`/adapter snapshot from the `Continuation` — and re-runs the activation locally, outside Beam.
- **A cache-only provider that can never reach a network.** Replay injects a `CacheOnlyLLMClient` implementing [`LLMClient`](../../../src/beam_agents/model/client.py:54) whose `complete` unconditionally raises `ReplayCacheMissError`. Because [`ActivationContext.call_model`](../../../src/beam_agents/core/context.py:469) is cache-first, every request whose response is in the snapshot's cache blob is served without touching the provider at all; only a genuine miss (or a `digest_only` entry) reaches the tripwire, which fails loudly naming the cache key. The client holds no transport, so "never hits the network" is true by construction, not by configuration.
- **Migration on load.** Every blob in the snapshot is checked against its `state_schema_version` and run through the same lazy migrations the pipeline applies (the `state-schema-migration` capability, sibling change `add-state-schema-migration`), so a snapshot exported from an older pipeline replays under newer code. A snapshot *newer* than the installed package is refused with an actionable error.
- **Outcome diffing.** The re-run's `ActivationResult` is compared against the traced record on the trace-comparable surface: activation status, the deterministic-serialized `TraceEvent` sequence (byte comparison — identifiers, attributes, and timestamps are all pure functions of the replayed inputs), and intent identity (`intent_id`, `tool_name`, kind, expiry). Divergence prints a structured diff and a non-zero exit code; outputs and the post-state memory blob, which have no traced counterpart, are reported as digests for inspection rather than diffed.

## Capabilities

### New Capabilities

- `state-snapshot-export`: the `export_request` envelope variant, the DoFn's read-only snapshot handling on the keyed stream, the `StateSnapshot` message contents, the `.snapshots` tagged output and its `snapshots_to` sink resolution, and the no-mutation guarantee.
- `replay-cli`: the `beam-agents-replay` console script — replay-bundle loading, schema-version checking and migration on load, input reconstruction, the cache-only provider and its loud-miss contract, local re-run via `run_activation`, outcome diffing, and the exit-code contract.

### Modified Capabilities

- `wire-schemas`: `AgentEnvelope`'s `oneof payload` gains the `export_request` variant, and the new `StateSnapshot` message is added. Both additive under `state_schema_version = 1`; no version bump.

## Impact

- **Depends on:** `add-trace-events` (C17) — replay reconstructs the traced outcome from correlated `TraceEvent`s, recovers `now_ms` from `ACTIVATION_START.start_ms`, and byte-compares re-emitted events against traced ones, all of which requires the deterministic identity and full event coverage that change ships. `add-state-schema-migration` (C32, sibling proposal in this batch) — snapshots outlive pipelines, so replay MUST run the same blob migrations on load that the DoFn runs lazily; the CLI consumes that capability's per-blob migration functions rather than reimplementing them.
- **New code:** `src/beam_agents/replay/` — `__init__.py`, `bundle.py` (snapshot/trace loading, schema-version check + migration, input reconstruction), `provider.py` (`CacheOnlyLLMClient`, `ReplayCacheMissError`), `diff.py` (traced-vs-replayed comparison and rendering), `__main__.py` (argument parsing per the effector pattern, exit codes). New `snapshot.py` (or equivalent) handling in `core/` for the export path.
- **Modified code:** [`protos/beam_agents.proto`](../../../protos/beam_agents.proto:130) + regenerated `_pb2.py` (`StateSnapshot`, `AgentEnvelope.export_request`); [`core/dofn.py`](../../../src/beam_agents/core/dofn.py:199) (route the export-request variant, read-only snapshot emission); `core/transform.py` (the `.snapshots` tagged output and `snapshots_to` resolution, mirroring the `traces_to` serialization the resolver already does for [`serialize_trace_event`](../../../src/beam_agents/observability/exporters.py:57)); [`pyproject.toml`](../../../pyproject.toml:47) (`beam-agents-replay` console script). No change to [`run_activation`](../../../src/beam_agents/core/loop.py:149) — being runnable outside Beam with an injected provider is the property this change consumes, not one it adds.
- **CI/build:** the replay package is pure-Python with no new dependencies (it imports no Beam at runtime beyond the generated protos and `core/loop.py`'s import surface); unit tests run offline in the default `pytest` tier. The regenerated `_pb2.py` must be diff-clean in CI. `core/dofn.py` is under the mutation gate — the new export route adds branches there, so `mutation-baseline.toml` ceilings are re-checked after implementation.
- **Gates:** golden-blob compat for the widened `AgentEnvelope` and the new `StateSnapshot`; a `semantics`-marked round-trip test (activation under `TestPipeline` → export → local replay reproduces byte-identical trace events and intents, zero provider calls); the coverage ratchet.
