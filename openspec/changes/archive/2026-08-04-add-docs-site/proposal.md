## Why

The runtime's documentation today is five standalone operator pages — `docs/{ci,effector,errors,metrics,traces}.md` — plus the README's runnable snippets. Each page is accurate, but there is no entry point, no navigation, no narrative from "event stream in" to "durable agent decision out", and no worked example of a single one of the workloads [project.md:5](../../project.md:5) names as targets: fraud triage, anomaly response, IoT reaction. There is no `examples/` directory at all. The closest thing the repo has to an example contract is the failure-streak DoFn copied verbatim from `docs/errors.md` into [test_failure_streak_alarm.py:8](../../../tests/examples/test_failure_streak_alarm.py:8), where the module docstring states the pattern outright: "the doc is the contract this test holds the runtime to." The `docs` dependency group reserved for site tooling has been empty since it was created ([pyproject.toml:101](../../../pyproject.toml:101)), and nothing validates the docs at all — a broken cross-reference between pages ships silently.

The timing is deliberate. With the effectively-once e2e gate (C16) and the adapter conformance matrix (C22) in place, the claims a docs site would lead with — side effects execute effectively once under real worker kills; every adapter exhibits identical lifecycle semantics on DirectRunner and Flink — are machine-verified release gates, not aspirations. This change builds the site and three examples, each a real runnable Beam pipeline driven by [FakeLLM](../../../src/beam_agents/model/fake.py:128) so every example runs offline in CI with no API keys and no docker, exactly like the unit tier requires.

## What Changes

- **Fill the empty `docs` dependency group with the site toolchain**: `mkdocs-material` (which brings `mkdocs` and `pymdown-extensions`). A repo-root `mkdocs.yml` builds the *existing* `docs/` tree as the site content root — the five operator pages join the nav unchanged — plus a new `docs/index.md` landing page that states what the runtime is (and is not, per the runtime-not-framework principle) and links each guarantee to the gate that enforces it. `make docs` runs `mkdocs build --strict`, so a broken internal link becomes a build failure.
- **A new `examples/` package with three single-module, runnable pipelines**, all driven by scripted `FakeLLM` rules and executable offline as `uv run python -m examples.<name>`:
  1. `examples/hello_world.py` — the minimal [`RunAgent`](../../../src/beam_agents/core/transform.py:471) pipeline: one keyed `AgentEnvelope`, one agent activation, one model call, one [`Complete`](../../../src/beam_agents/core/agent.py:83) output. The smallest honest program on the runtime surface.
  2. `examples/fraud_triage.py` — the suspension/HITL flow on a transaction stream: the agent triages via the model, stages an approval request with [`ctx.request_approval`](../../../src/beam_agents/core/context.py:559), returns [`Suspend`](../../../src/beam_agents/core/agent.py:90); one account's approval re-enters on the same key and resumes to a freeze decision, another account's deadline elapses on a `TestStream` processing-time advance and takes the fail-closed [`Deny`](../../../src/beam_agents/hitl.py:98) route.
  3. `examples/iot_reaction.py` — streaming reaction over a `TestStream` of sensor readings: keyed rolling working memory via [`Memory.append`/`ring`](../../../src/beam_agents/memory/facade.py:165), a threshold breach triggers the model call and a reaction output; quiet readings complete without one.
- **One docs page per example** (`docs/examples/*.md`) that renders the runnable module *by inclusion* (`pymdownx.snippets`), so the code shown on the site and the file the tests execute are the same bytes — the verbatim-copy pattern from `docs/errors.md`, upgraded so drift is impossible by construction rather than policed by convention.
- **One test module per example** in `tests/examples/`, executing the exact module the docs render under `TestPipeline`/`TestStream` and asserting the documented outputs — the same doc-example-verified-by-test pattern as [test_failure_streak_alarm.py:8](../../../tests/examples/test_failure_streak_alarm.py:8), running in the offline unit tier ([Makefile:27](../../../Makefile:27)).
- **CI/deploy wiring**: a new `docs.yml` workflow — strict build on pull requests, GitHub Pages deployment (official Pages actions, no `gh-pages` branch) on pushes to `main`. The two out-of-tree relative links in [ci.md:4](../../../docs/ci.md:4) are rewritten as repository URLs so `--strict` passes.
- **Examples are held to the repo's code standard**: `examples/` joins the `ruff` and `mypy --strict` surfaces (with the same per-module Beam-untyped-API relaxations every pipeline-driving test module already carries), and stays out of the wheel — `hatchling` packages only `src/beam_agents`, unchanged.

## Capabilities

### New Capabilities

- `docs-site`: the buildable, deployable documentation site — toolchain in the `docs` dependency group, strict build as a CI gate, the existing operator pages plus a landing page in its nav, example pages rendered by verbatim inclusion of the runnable source, and Pages deployment from `main`.
- `runnable-examples`: the three example pipelines and their contract — offline `FakeLLM`-driven execution with no credentials or docker, self-contained imports (runtime + Beam only, never `tests/`), doc-example-verified-by-test enforcement in the unit tier, and lint/type parity with the rest of the repo.

### Modified Capabilities

None. No existing runtime, effector, observability, or adapter contract changes: the site and examples consume `RunAgent`, `AgentConfig`, `HitlPolicy`, the `Memory` facade, and `FakeLLM` exactly as specified today, and every edit to an existing file (link rewrites in `docs/ci.md`, dependency-group/config additions in `pyproject.toml`, a README pointer, Makefile targets) is non-normative packaging around unchanged behavior. If writing an example had required a runtime change, that would be a finding to raise, not something to fold in here.

## Impact

**Depends on** C16 [`add-effectively-once-e2e-gate`](../add-effectively-once-e2e-gate/proposal.md) and C22 [`add-adapter-conformance-matrix`](../add-adapter-conformance-matrix/proposal.md): the landing page documents effectively-once side effects and adapter-uniform lifecycle semantics as *verified* properties by pointing at those gates, and the fraud example's suspend/approve/timeout flow is precisely the lifecycle the conformance matrix pins (its suspension-resume and approval-timeout scenarios) and whose zero-lost-approvals property the e2e gate proves at volume — the site must not document promises nothing enforces. Also consumes, unchanged: `RunAgent`/`AgentConfig` ([transform.py:395](../../../src/beam_agents/core/transform.py:395)), the `Agent` outcome contract ([agent.py:132](../../../src/beam_agents/core/agent.py:132)), `HitlPolicy` routing ([hitl.py:136](../../../src/beam_agents/hitl.py:136)), the `ActivationContext` surface ([context.py:370](../../../src/beam_agents/core/context.py:370)), and `FakeLLM` ([fake.py:128](../../../src/beam_agents/model/fake.py:128)).

**New code:** `mkdocs.yml`; `docs/index.md`; `docs/examples/{hello-world,fraud-triage,iot-reaction}.md`; `examples/__init__.py`, `examples/hello_world.py`, `examples/fraud_triage.py`, `examples/iot_reaction.py`; `tests/examples/test_hello_world.py`, `tests/examples/test_fraud_triage.py`, `tests/examples/test_iot_reaction.py`, `tests/examples/test_docs_snippets.py`; `.github/workflows/docs.yml`.
