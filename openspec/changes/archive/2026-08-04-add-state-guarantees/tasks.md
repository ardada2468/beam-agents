## Revisions

### Revision 1 — the resolver picks the latest release *at or below* head, not simply the latest

Design D3 says the resolver "discovers the latest beam-agents release on PyPI". Taken literally, a PyPI release newer than the checkout (a hotfix tagged from another branch, or a rolled-back head) would make the gate launch at N+1 and update *down* to head — a downgrade, which D1 declares explicitly unsupported and which the gate must therefore never test. `latest_release()` accordingly restricts candidates to versions at or below head's own version, and falls back to the bootstrap leg when none qualifies, with the reason spelled out in the report. This narrows the resolver without touching the promise: the gate still runs exactly one forward hop. Covered by `test_a_release_newer_than_head_is_never_chosen`. The design document's D3 wording is left as-is (it describes intent correctly); this note records where the implementation is more specific.

### Revision 2 — the Impact section omits `pyproject.toml`, which this change must edit

The proposal's Impact section lists the new test files, `nightly.yml`, `Makefile` and `docs/ci.md`, but no lint/type configuration. `tests/dataflow/_update/pipeline.py` is a real Beam pipeline and the harness reads unstubbed GCP client payloads, so `mypy --strict` and `ruff` need the same two per-module relaxations every other Beam-driving and lazy-import-by-design module in this repo already carries:

- `[tool.ruff.lint.per-file-ignores]`: `PLC0415` for `tests/dataflow/_update/*` (the GCP clients are imported inside the constructors that need them, so the modules import cleanly in the offline lane where the gate is merely collected — the same rationale as `tests/semantics/_e2e/*`), and `PLR0915` for the gate module (one scenario told in phases — the same rationale as `tests/semantics/test_effectively_once_e2e.py`).
- `[[tool.mypy.overrides]]`: `no-untyped-call`/`type-arg`/`no-any-return` for `tests.dataflow.*` — the standard Beam-untyped-API relaxation.

No other configuration changed, and no `src/` file was touched.

### Revision 3 — a changelog fragment is added, which the Impact section also omits

`CONTRIBUTING.md` and `changelog.d/README.md` require one fragment per OpenSpec change. The pre-commit hook only *enforces* it for `src/` edits, so this change would pass without one, but `docs/state-compat.md` is a published, user-facing policy: `changelog.d/add-state-guarantees.docs.md` (type `docs`, PATCH-compatible, so it does not perturb the versioning policy) is committed with it.
