## Revisions

### Revision 1 — `pyproject.toml` needs a mypy per-module relaxation (not named in Impact)

The proposal's Impact section listed `src/beam_agents/__init__.py` and `tests/test_import.py` as the only modified files. Implementation showed that is not sufficient: under `mypy --strict`, every Beam call site (`beam.ParDo`, `with_output_types`, `TestPipeline`, `assert_that`, `beam.Map`) reads as `no-untyped-call`, and Beam's `PTransform`/`PCollection` generics ship unparameterized (`type-arg`). Every Beam-driving module in the repo already carries a per-module `disable_error_code` override for exactly this — `beam_agents.core.transform`, `beam_agents.actions.write_intents`, `beam_agents.observability.otlp`, and each pipeline-driving test module.

`pyproject.toml` therefore gains one override block covering `beam_agents.keys`, `tests.keys.test_shard_keys_transform`, and `tests.examples.test_shard_fanout` with `["no-untyped-call", "type-arg", "no-any-return"]`, matching the existing precedent verbatim. Note the relaxation does **not** weaken the two pure functions: `shard_key`/`unshard_key` touch no Beam API, so no relaxed code applies to them. `tests/keys/test_shard_key.py` is deliberately left out of the block — it is pure-Python and stays fully strict. The proposal's Impact section has been amended to name `pyproject.toml`.

### Revision 2 — the worked examples are anchored to the harness's tier dimensions, not to a committed median

Task 4.3 and design D6 say the doc's figures are "filled in from harness runs during implementation". C33's own `docs/benchmarks.md` forbids exactly that when the run is on developer hardware: *"Never seed the baseline from developer hardware. The gate runs on CI hardware; a laptop-derived number either blocks every nightly or is so loose it catches nothing."* — and `benchmark-baseline.toml`'s `[medians_ms]` table is still unseeded for the same reason (no hosted-runner nightly has run yet). Committing a locally measured activations/sec into a doc would be the same error one layer up, and would be an unattributable number the moment it went stale.

So the doc cites the harness's **dimensions** — the benchmark names (`noop_throughput`, `overhead_50ms`/`overhead_500ms`/`overhead_2000ms`, `suspension_roundtrip`, `state_commit_{1,16,64,100}kib`) and the tier latencies those benchmarks actually configure (50/500/2000 ms, `benchmarks/_harness.py:TIERS_MS`) — and builds its arithmetic on them, with each worked example naming the benchmark its input comes from and pointing the reader at their own `bench-report.md` for the machine-specific median. Nothing in the doc is an unattributed figure, which is what the requirement is protecting. This satisfies the spec's "reference the benchmark harness's dimensions and measured single-key activation rates rather than unattributed figures" without minting a number the repo's own benchmark policy says must not be committed.
