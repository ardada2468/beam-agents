## Why

The outbox leg is built — `RunAgent` stages `ToolIntent`s, `WriteIntents` lands them key-partitioned on the outbox topic, and `hitl.refuse_expired` is the pure layer-2 expiry guard — but **nothing consumes that topic**. Every side effect the runtime is designed around currently stops at the outbox: no tool ever executes, no `ToolResult` is ever published, so the re-injection path (`ToolResult` → same key → `_resume`) is unreachable and the effectively-once argument (deterministic `intent_id` + dedup at the executor) has no executor to dedup at. This change ships the reference effector: the external service that closes `intents → execute → results → re-injection` and turns "effectively-once side effects" from a design claim into a running, testable property.

## What Changes

- **New `effector/` reference service** (`src/beam_agents/effector/`), an asyncio service that is *not* imported by the pipeline and imports no Beam. It consumes intents, dedups, executes, and publishes `ToolResult`s. Shipped as a library plus a `beam-agents-effector` console entry point and a config dataclass; deployment (container, replicas, scaling) stays out of scope.
- **Kafka and Pub/Sub consumers behind one `IntentSource`/`ResultSink` protocol pair.** `kafka://<brokers>/<topic>` consumes via a **consumer group** whose partition assignment is the unit of key affinity: intents were written keyed by `entity_key`, so a key's intents live on one partition, one partition is owned by one consumer, and that consumer processes it sequentially — per-key order survives horizontal scale-out. `pubsub://<project>/<subscription>` consumes a subscription with **ordered delivery** enabled, processing one `ordering_key` at a time. Offsets/acks commit only **after** the result is published and the dedup record is terminal, so a crash re-delivers rather than loses.
- **Pluggable dedup with a three-state claim protocol.** A `DedupStore` protocol with one operation set — `claim(intent_id, lease_ms)` → `CLAIMED` / `IN_FLIGHT` / `DONE(result)`, plus `complete(intent_id, result, ttl_ms)` and `release(intent_id)`. Two implementations: **Redis** (`SET key value NX PX lease` for the claim, `SET` of the serialized result for completion) and **Bigtable** (`CheckAndMutateRow` conditional on the row's absence for the claim, a second conditional mutate for completion). A redelivered intent that is already `DONE` **republishes the stored result and does not re-execute**; an intent seen as `IN_FLIGHT` is left for the current owner. This is the dedup half of correctness invariant 2.
- **Execution against a shared `ToolRegistry`.** The effector is constructed with the *same* registry the agent declares its tools from, so one `@tool` definition serves both sides. Because correctness invariant 5 makes `side_effect=True` tools unrunnable in-pipeline (`Tool.__call__` and `ToolRunner.run` both raise `SideEffectToolError`), the effector gets its own `EffectorToolRunner` — the single, explicitly named execution path that is *permitted* to run side-effecting tools, and that conversely **refuses `side_effect=False` tools** (a read-only tool reaching the outbox is a runtime bug, not an effect to perform). Arguments are validated against the tool's Pydantic model before the callable runs.
- **`expires_at` refused before anything else.** Every intent passes through `hitl.refuse_expired` *before* it is claimed or executed; an expired intent publishes `ToolResult(status=EXPIRED)` and is marked terminal. This is layer 2 of correctness invariant 6, and it is checked ahead of dedup so an expired intent can never consume a claim or a tool call.
- **Approval intents are routed, never executed.** `ToolIntent.kind == APPROVAL` is published to a configured approval channel (a topic) instead of being run; the human/automated decision returns on the approvals topic as an `AgentEnvelope.Approval`, which the effector does not own.
- **Typed, total outcome mapping.** Every consumed intent produces exactly one published `ToolResult`: `OK` (tool returned), `ERROR` (tool raised or timed out — the callable ran and its effect is unknown), `EXPIRED` (past `expires_at_ms`), `REJECTED` (unknown tool, non-side-effecting tool, or argument-validation failure — the callable was never invoked). Results are published keyed by `entity_key` so re-injection lands on the originating key.

## Capabilities

### New Capabilities
- `effector-service`: The consume → refuse-expired → dedup → execute → publish → commit pipeline of the reference effector, including the Kafka/Pub/Sub source and sink adapters, key-partitioned consumer-group ordering, at-least-once commit ordering, bounded retry, and the service configuration/entry point.
- `effector-dedup`: The `DedupStore` protocol and its three-state claim/complete/release contract, the Redis `SET NX PX` implementation, the Bigtable `CheckAndMutateRow` implementation, lease expiry semantics, and the stored-result republish path that makes redelivery free of re-execution.
- `effector-execution`: Registry-backed execution of side-effecting tools via `EffectorToolRunner` — argument validation, the inverted side-effect guard, per-tool execution timeout, approval-kind routing, and the total intent → `ToolResult` status mapping.

### Modified Capabilities
- `tool-registry`: The current requirement states that a `side_effect=True` tool raises on *any* direct invocation. That stays true for every in-pipeline path, but the spec must now name the one sanctioned exception — the effector's execution path — and state its inverse guard (the effector refuses `side_effect=False` tools), so "side effects only via intents" remains a closed statement rather than a rule with an undocumented hole.

## Impact

- **New code:** `src/beam_agents/effector/` — `service.py` (the consume/execute/publish loop), `sources.py` + `sinks.py` (Kafka/Pub/Sub adapters behind protocols), `dedup.py` (protocol + Redis + Bigtable), `runner.py` (`EffectorToolRunner`), `config.py` (`EffectorConfig`, URI validation), `__main__.py` (entry point).
- **Modified code:** `src/beam_agents/tools/registry.py` / `runner.py` gain nothing functional but the docstring contract is tightened; the effector reaches the underlying callable through an explicit, named accessor rather than a private attribute, so the guard's one sanctioned bypass is auditable.
- **Schemas:** none. `ToolIntent` (with `kind`, `expires_at_ms`, `attempt`) and `ToolResult` (with its four terminal statuses) are already sufficient; no proto edit, no `state_schema_version` bump.
- **Dependencies:** a new optional `effector` dependency group — `aiokafka`, `google-cloud-pubsub`, `redis`, `google-cloud-bigtable`. The core package must remain installable and unit-testable without any of them (imports stay lazy, behind the adapter seams), and `beam_agents/__init__.py` does **not** re-export effector symbols.
- **Public API:** the effector is a separate service surface (`beam_agents.effector`), deliberately outside the `beam_agents/__init__.py` public API listed in project conventions.
- **Tests:** unit tests run offline with no docker against in-memory source/sink/dedup fakes, covering ordering, commit-after-publish, expiry refusal, claim states, and status mapping. `-m integration` covers Redpanda + Redis (and the Pub/Sub emulator) wiring. A `-m semantics` gate asserts effectively-once end-to-end: replaying the same `intent_id` stream with induced worker kills yields exactly one execution per `intent_id`.
- **Downstream:** completes `.intents → outbox → effector → results topic → re-injection`, making the HITL and continuation paths exercisable end-to-end for the first time.
